## [0.1.1] - 2026-11-04
### Fixed
- **SQLite WAL Non-Blocking MVCC Snapshot Isolation (`Cache = SqliteCacheMode.Default` — [`SqliteWalPool.cs`](file:///<PROJECTS_ROOT>/Foundation/Dev/src/Foundation.Core/SqliteWalPool.cs))**:
  - Replaced `Cache = SqliteCacheMode.Shared` with `Cache = SqliteCacheMode.Default` and increased the default `busyTimeoutMs` from `5000` to `15000` (`15s`). In SQLite WAL mode, `SQLITE_OPEN_SHAREDCACHE` overrides lock-free WAL snapshot isolation with process-wide table locks (`SQLITE_LOCKED`, Error 6), which ignore `PRAGMA busy_timeout` and caused concurrent readers (`/api/v1/entries`, `/api/v1/jobs/queue`) and batch checkpoint writers to collide with `SQLite Error 6: 'database table is locked: entry_files'`.
  - Added [`SqliteWalPool_UsesDefaultCacheAndSupportsConcurrentReadersDuringWriteTransaction`](file:///<PROJECTS_ROOT>/Foundation/Dev/tests/Foundation.Tests/FoundationCoreTests.cs) (`10/10` passing tests in `Foundation.Tests`), updated `ShellBrandingOptions.SdkVersion` and `foundation_core.SDK_VERSION` to `"0.1.1"`, and published `v0.1.1` binaries to `<PROJECTS_ROOT>\SharedLibs\Foundation\v0.1.1\` and `<PROJECTS_ROOT>\ShadowLibrary\Dev\lib\`.
